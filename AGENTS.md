# Правила разработки «Герой Сказок»

## Текущий статус выпуска

Независимый QA коммита `1a491068002084fbc8647469fda54ba5aead415f` завершён со статусом **PARTIAL**. Выпуск остаётся **HOLD**. По результатам QA остаточные семейные данные могут быть доступны новому аккаунту с тем же email. Зелёный CI не снимает этот блокер. Требуются отдельное исправление и независимое подтверждение изоляции данных на SHA нового кандидата.

## Обязательный порядок работы

- Начинай с номера задачи, исходного SHA, границ изменений и критериев приёмки. Сохраняй чужие изменения и артефакты, включая `parent-pin-stage1.bundle`. Этот bundle не добавляй в Git.
- Работай в отдельном worktree. Для задач процесса выпуска сохраняй `main` и `fix/security-audit-2026` без изменений. На правки приложения требуется отдельная задача.
- Push, merge, deploy, публикация релиза и изменение настроек GitHub требуют отдельного явного разрешения владельца.
- Используй синтетические аккаунты и изолированные сервисы. Не обращайся к production API из тестов. Не включай реальные семейные данные, токены, PIN и секреты выпуска в тесты, задачи или отчёты.
- Из `magic_app/` запускай `npm ci` в чистом окружении, затем `npm test -- tests/security`, `npm test`, `npm run type-check` и `npm run test:syntax`. Для стандартного прогона используй `RUN_API_TESTS=0`. Установить `RUN_API_TESTS=1` можно только на согласованном изолированном стенде.
- Привязывай отчёт к SHA и среде. Указывай команды, результаты PASS / FAIL / SKIP / НЕ ПРОВЕРЕНО, причины пропусков, ссылки на свидетельства и владельцев блокеров.
- Изменения доступа, изоляции, согласий и удаления данных передавай на независимое ревью. Разработчик передаёт SHA кандидата, QA определяет необходимый объём перепроверки после каждого изменения. Решение о выпуске принимает владелец.
- Для повторяемой работы применяй `$security-audit`, `$qa-release` и `$release-manager`. Запускай субагентов по явному поручению владельца.
