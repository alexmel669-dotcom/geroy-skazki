# «Герой Сказок» на Ubuntu 24.04

Скрипт предназначен для отдельной Ubuntu 24.04 с systemd и доступом в интернет. Для репетиции подойдёт и виртуальная машина. Покупать VPS для сборки APK не требуется. На компьютере установщика должны быть три файла из этой папки: `deploy.sh`, `env.example`, `DEPLOY_INSTRUCTIONS.md`.

## Подключение и установка

1. В панели сервера найдите его IP, имя пользователя SSH и отпечаток SSH-ключа сервера. В Windows откройте PowerShell **в папке с файлами**. В командах ниже замените `ubuntu` и `SERVER_IP` своими значениями. При первом подключении сверьте отпечаток, затем подтвердите подключение. Если провайдер выдал файл ключа, добавьте `-i "путь-к-ключу"` к командам SSH и SCP.

   ```powershell
   ssh ubuntu@SERVER_IP "mkdir -p ~/geroy-install"
   scp deploy.sh env.example ubuntu@SERVER_IP:~/geroy-install/
   ssh ubuntu@SERVER_IP
   ```

2. В открывшемся окне Ubuntu выполните:

   ```bash
   cd ~/geroy-install
   sudo bash deploy.sh
   sudo nano /etc/geroy-skazki/.env
   ```

   Впишите свой адрес после `ADMIN_EMAIL=`. Первый запуск уже сгенерировал разные пароли и токены. Можно задать собственный `REDIS_PASSWORD` до установки: от 24 символов, латинские буквы, цифры, `_` и `-`. Запишите пароль администратора в свой менеджер паролей. В nano сохраните файл через **Ctrl+O**, **Enter**, выйдите через **Ctrl+X**. Для закрытой проверки оставьте `PUBLIC_DOMAIN` пустым. Ключи ИИ и голоса необязательны. Рабочий файл с секретами находится вне Git.

3. Установите приложение:

   ```bash
   sudo bash deploy.sh
   ```

   Скрипт клонирует ветку `fix/security-audit-2026`. Для закрытого репозитория заранее настройте на сервере SSH deploy key с доступом на чтение для пользователя, запускающего Git (здесь root), проверьте ключ хоста GitHub. Тогда вместо команды выше выполните `sudo env REPO_URL=git@github.com:alexmel669-dotcom/geroy-skazki.git bash deploy.sh` при первом клонировании.

4. Дождитесь сообщения «Готово» с SHA. На **Windows** откройте второе окно PowerShell и оставьте в нём работающей команду:

   ```powershell
   ssh -N -L 127.0.0.1:8080:127.0.0.1:8080 ubuntu@SERVER_IP
   ```

   В браузере откройте [регистрацию](http://127.0.0.1:8080/register.html), создайте вымышленную семью и откройте [родительский кабинет](http://127.0.0.1:8080/parent.html) с её PIN. **Ctrl+C** закрывает туннель. Сервер продолжает работать.

## Что установлено и как проверить

Nginx работает на хосте. Docker Compose устанавливает Node.js 24 с PM2, выполняет `npm ci --omit=dev` по lock-файлу приложения и запускает его на порту 3000. Для клиента `@upstash/redis` предусмотрен HTTP-шлюз к обычному Redis. Только Nginx принимает запросы к сайту извне в публичном режиме. Redis и шлюз доступны внутри сети контейнеров. Данные Redis и локальной аналитики хранятся в отдельных постоянных томах. Скрипт проверяет HTML через Nginx и команды PING и EVAL через тот же клиент Redis, которым пользуется приложение. [Описание HTTP-шлюза](https://github.com/hiett/serverless-redis-http)

```bash
sudo docker ps --filter label=com.docker.compose.project=geroy
sudo docker logs --tail 40 geroy-app-1
curl -I http://127.0.0.1:8080/app.html
```

Повторный запуск `sudo bash deploy.sh` из папки установщика берёт текущую вершину той же ветки и сохраняет заполненный файл настроек и тома. Перед обновлением рабочего сервера сделайте резервную копию данных и настроек.

## Когда понадобится публичный HTTPS

Для первого публичного запуска направьте A-запись домена на сервер. При наличии AAAA-записи она также должна вести на доступный по IPv6 сервер (для этого потребуется IPv6-конфигурация Nginx); проще начать только с A-записи. Разрешите входящий TCP на 80 и 443 в правилах провайдера и сервера, сохранив доступ по SSH. Укажите домен без `https://` в `PUBLIC_DOMAIN`, затем повторите запуск. Скрипт настроит HTTPS, сертификат Let's Encrypt и его обновление. Выпуск сертификата требует доступного из интернета домена. В этой версии APK использует API домена `https://geroy-skazki.ru`.

## Сборка APK без VPS

В репозитории откройте [Actions → Build APK](https://github.com/alexmel669-dotcom/geroy-skazki/actions/workflows/build-apk.yml), нажмите **Run workflow**, выберите ветку **fix/security-audit-2026** и подтвердите. По окончании откройте запуск и скачайте ZIP **geroy-skazki-debug** из раздела **Artifacts**. Внутри находится `app-debug.apk`. Для ручного запуска нужен доступ на запись. [Ручной запуск GitHub Actions](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow)

Workflow сначала загружает тестовый APK, затем собирает подписанные APK и AAB. Для последних шагов нужны существующий ключ подписи приложения и секреты GitHub `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`. Даже при сбое подписи уже загруженный debug-артефакт останется в этом запуске. После установки проверьте на телефоне запуск, сессию, разрешение на микрофон и запись голоса. Подпись и публикация — отдельные действия.

### Локальная сборка на проверенном компьютере

Для SHA `554c81e` успешно выполнены создание проекта Capacitor, синхронизация, генерация ресурсов и Android-патч. Gradle 8.14.3 остановился на JDK 25 с ошибкой `Unsupported class file major version 69`; у сгенерированного проекта исходный и целевой уровень Java 21, `compileSdk = 36`.

1. Установите **Temurin JDK 21** и выберите его для Gradle в Android Studio. Для терминальной сборки укажите эту же папку в `JAVA_HOME`. Node.js 24 и Android Studio уже установлены.
2. В **Tools → SDK Manager** установите **Android SDK Platform 36**. Build-Tools 36.0.0 уже есть. Для запуска через терминал укажите `ANDROID_HOME` на папку Android SDK. Если требуется установка пакетов из терминала, добавьте **Android SDK Command-line Tools (latest)**.
3. Шаги создания проекта и сборки перечислены в `.github/workflows/build-apk.yml`. Патч использует Bash и Python 3. Отдельный системный Gradle не требуется: в созданной папке `android-app/android` на Windows используется `gradlew.bat assembleDebug`.
4. Текущий патч вывел 0 совпадений для `onPermissionRequest` в MainActivity. Регистрация GamePlugin присутствует. Проверка микрофона на устройстве остаётся обязательной для оценки голосовой функции. Версии пакетов Capacitor в workflow устанавливаются без lock-файла, поэтому результат следующей сборки может отличаться.
